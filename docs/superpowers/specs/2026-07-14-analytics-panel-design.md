# Analytics Panel — Design Spec

Date: 2026-07-14
Status: Approved by user, pending implementation plan

## Summary

Add a new toggleable HUD panel, `#analytics-panel`, with three stacked
sections — **Network** (bar chart), **Markets** (live stock tracker), and
**Intel** (hydrogen industry news) — to make the console feel more alive
without adding more decorative chrome. This is additive to the existing
JARVIS-style HUD (`hud.css`, `hud.js`) and follows the project's existing
patterns: classic scripts sharing one global scope, static curated data
files regenerated by a script, and client-side live fetches with graceful
fallback (see `07-live.js`).

## Goals

- Give the console a "living data" feel (animated counters, live-linked
  bars, live market ticks) rather than more sci-fi decoration.
- Reuse existing visual language: glass panels, `--h-*` taxonomy colors,
  `--cyan` accents, HUD corner brackets, boot-style fill animations.
- Stay within the project's constraints: static site, no build step, no
  backend, no exposed paid API keys.

## Out of scope

- Historical price charts / candlesticks for the stock tracker (current
  price + % change + sparkline only).
- Full-text news article display (headline + one-line summary + link-out
  only, respecting source paywalls).
- Server-side/scheduled automation of the refresh scripts (manual rerun,
  same as `build-iea.py`).

## 1. Panel shell

- New `#analytics-panel` in `index.html`, `hidden` by default.
- Styling in `style.css`/`hud.css`: same visual language as `#detail-card`
  (`.glass`, corner brackets from `hud.css`), but docked on the **left**:
  `top: 66px; left: 64px; width: 320px; max-height: calc(100vh - 130px);
  overflow-y: auto;` — clears the vertical `#layer-dock` icon strip and
  never collides with `#detail-card` on the right.
- New "▤ Analytics" toggle button added to `#action-capsule` (top-right),
  next to the existing "▶ Tour" button. Click toggles `hidden` on the panel
  and an `active` class on the button (same convention as `.dock-btn.active`).
- Panel has three section headers (`.stats-head`-style, matching the
  existing detail-card convention): `NETWORK COMPOSITION`, `MARKETS`,
  `INTEL`.

## 2. Network section (bar graphs)

- One horizontal bar per H₂ color/taxonomy tier: green, blue, pink,
  turquoise, gray, brown, mfg — using the existing `--h-*` CSS tokens so
  colors match the legend exactly.
- Each row: label, thin track (`.bar-track`), fill (`.bar-fill`,
  color-coded), node count.
- Bars animate width-in on panel open (reuse the `boot-fill` keyframe
  pattern from `hud.css`).
- **Live-linked to filters**: recomputed whenever `applyFilters()` runs, so
  the bars reflect only the currently filtered status/region — same hook
  point `iea-layer.js` already uses to patch `applyFilters`.
- Data source: count features across `D.upstream`, `D.production`,
  `D.manufacturing`, `D.storagePoints`, `D.pipelines`, `D.endUse` (+ IEA
  tier if visible) grouped by `properties.color`, filtered by the current
  `TOGGLE_MAP`/region/status state — same feature arrays `04-search.js`'s
  `renderStats()` already assembles.

## 3. Markets section (stock tracker)

- Live client-side fetch, same pattern as `loadLiveStations()` in
  `07-live.js` (fetch → render → `catch` → fallback state).
- Ticker list (fixed, curated): PLUG (Plug Power), BE (Bloom Energy), BLDP
  (Ballard Power), ITM.L (ITM Power), NEL.OL (Nel ASA), FCEL (FuelCell
  Energy), APD (Air Products), LIN (Linde), CMI (Cummins), GTLS (Chart
  Industries).
- Data provider: Finnhub free-tier `/quote` endpoint (CORS-friendly, one
  call per ticker). Unlike AFDC, **Finnhub has no public demo key** — a
  `FINNHUB_KEY` constant in `01-core.js` starts empty/placeholder.
  - If unset or a fetch fails: section shows a graceful "configure API
    key" fallback state (matching the existing `setStatus("fallback", …)`
    convention), never a broken/empty UI.
  - Once configured, prices refresh on a 60s interval while the panel is
    open only (no background polling when collapsed, to conserve the free
    rate limit).
- Each row: ticker, last price, % change (green/red via existing
  `--green-ok`/`--red` tokens). **Amended 2026-07-14, post-implementation
  review:** the per-row sparkline originally specified here was dropped —
  symbol/price/%-change already convey the key signal, and a sparkline
  would need Finnhub's day-high/low fields plus real rendering complexity
  for a nice-to-have. Not built.
- `DEPLOY.md` gets a new "Before public launch" bullet: obtain a personal
  Finnhub free-tier key, same treatment as the existing NREL `DEMO_KEY`
  note.

## 4. Intel section (news)

- List of ~6–8 headline cards: source tag (pill, same style as
  `.ticker-tag`), one-line LLM-written summary, relative date, link-out to
  the original article.
- Data source: **static, scripted refresh** — new `js/news-data.js`
  (`window.HYDROGEN_NEWS = [...]`), generated by a new dev-only script
  `build-news.py` (same pattern/naming as `build-iea.py`), committed to
  the repo. Not fetched live in the browser.
- `build-news.py` responsibilities:
  1. Pull public RSS feeds: IEA news, Bloomberg Green, NYT Climate, S&P
     Global, Reuters Energy, Hydrogen Insight, Recharge News.
  2. Filter entries to hydrogen-relevant keywords (hydrogen, electrolyzer,
     H2, fuel cell, etc.), most-recent first, cap at ~8–10 candidates.
  3. Call the Claude API (`ANTHROPIC_API_KEY` read from local env, never
     committed) to write a punchy one-line summary per article in the
     existing "INTEL" HUD voice.
  4. Write `js/news-data.js` as a plain JS global assignment (same shape
     as `iea-data.js`'s generated output).
- Rerun manually whenever fresh news is wanted — no scheduling/automation
  built.
- README/DEPLOY docs updated with the rerun instructions, mirroring the
  existing "Refresh IEA data" section.

## Error handling

- Markets section: missing/invalid API key or fetch failure → fallback
  state, not a broken UI (matches `07-live.js` convention).
- Intel section: if `news-data.js` fails to load or is empty, section
  collapses/hides gracefully (same defensive check pattern as
  `startTicker()`'s `if (!facts.length || !el) return;`).
- Network section: no new failure modes — pure client-side aggregation of
  already-loaded data.

## Testing

  verify Markets fallback state renders when `FINNHUB_KEY` is empty,
  verify Intel section renders from a hand-written sample
  `news-data.js` before wiring the real script.
- Extend `js/smoke-test.js` with a check that `window.HYDROGEN_NEWS` (once
  present) is an array, mirroring its existing IEA data assertions.
